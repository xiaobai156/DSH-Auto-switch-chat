# DSH 会话自动交接

已在 Windows 上的 DSH Desktop Beta 2.0.17-beta.1（DSH core 0.2.0-rc.2）验证。插件包名为 `@local/dsh-session-handoff`。

- 输入框下方、上下文百分比右侧显示当前会话成功压缩的次数。
- 每个会话分别计数；手动和自动的总结压缩均计入，失败压缩和工具结果裁剪不计入。
- 累计达到 3 次后，等模型当前一轮正常回复结束并空闲，再总结最后处理的任务。
- 创建同工作区的新会话，名称沿用原名称并递增“（续1）”“（续2）”。
- 有未完成任务时自动继续；全部完成时只保存交接内容，保持空闲。
- 保留旧会话，新会话从 0 次开始。历史会话可以正常回看。
- 总结失败不会丢弃旧会话；总结期间有新的用户输入时，等新一轮回复结束再交接。

首次启用会补算历史压缩次数，但不会仅因安装插件而批量交接旧会话。

## 安装

在 DSH 的插件管理页使用以下 Git 仓库地址安装，并启用插件：

```text
https://github.com/xiaobai156/DSH-Auto-switch-chat.git
```

也可以先克隆仓库，再通过插件管理页安装克隆目录的绝对路径。通过本地目录链接安装时，请保留该目录。
更新已加载的版本后需要重启 DSH，以重新加载 JavaScript 模块。
卸载时在插件管理页移除该插件；历史会话由 DSH 自身保存。

## 测试

需要 Node.js 24 和上面已验证版本的 DSH。核心测试可直接运行：

```powershell
node --test backend.test.mjs
```

原生运行时测试需要设置 `DSH_TEST_CORE_ROOT`，指向 DSH 安装目录中 `resources/app/node_modules/@deepseek-ai` 的绝对路径，再运行：

```powershell
$env:DSH_TEST_CORE_ROOT = 'C:/path/to/DSH Desktop Beta/resources/app/node_modules/@deepseek-ai'
node --test backend.test.mjs runtime.test.mjs
```

运行时测试使用隔离的临时会话目录和确定性模型，不读取真实用户配置或调用云模型。

## 更新记录

1.0.2（2026-10-08）：

- 从原始会话日志收集原生文件/图片引用并去重，交接后可继续读取已被摘要压缩的附件。旧图片以 DSH 的 offloaded 引用保存，可在新会话中查看和用工具读取，避免重复上传全部历史图片。
- 网络、超时、临时服务故障和限流失败在 5/15/45 秒后重试，最多三次；凭据、余额和无效摘要错误不自动重试。失败状态提供“重试交接”按钮，复用原消息和目标会话编号；新输入取消旧总结的重试。
- 摘要读取当前模型的上下文容量并预留输出与请求余量，按 UTF-8 字节保守估算输入，优先完整保留用户要求、跟进及原生压缩检查点，再分配回复/工具日志的容量；缺少容量元数据时使用 8192 的保守预算。要求和检查点合计超预算时保留原会话，并提示切换更大上下文模型后重试。预算为估算，不是模型专用 tokenizer 的精确计数，因此小容量模型可能较早触发保护。
- 等待状态每 10 秒检查；达到阈值时立即检查，交接中每 2 秒检查；后台暂停，回到前台立即恢复，已交接会话停止轮询。
- 补充真实附件存储与冷启动、重试去重、模型容量边界及 Chromium/React 界面回归。
